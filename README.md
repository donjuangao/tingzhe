# 听着

**一个给 [Claude Code 桌面版](https://claude.com/claude-code) 做语音对话的 macOS 工具。**

打开语音对话之后：你张嘴说话 → 它转写、修正专名、替你发送 → Claude 的回复它念给你听 →
**你一开口，它立刻闭嘴**。中间你不用碰键盘，也不用点发送。

这就是它被做出来的原因。下面所有设计（攒句子、打断、静音、会话选择）都是围着这件事转的。

---

它还有**另一半**：**按住一个键说话，松开，字就出现在你当前那个输入框里** —— 任何输入框，
跟 Claude 无关。这半不需要 Claude Code，也能单独用，很多人可能只用这半。

但先说清楚：**主线是前者。**

---

## ⚠ 先说清楚这东西靠什么

两半的依赖**完全不同**，装之前先对号入座：

| | 靠什么 | 谁能用 |
|---|---|---|
| ⭐ **语音对话**（主线）<br>你说它发送、它念给你听 | **Claude Code 桌面版** + 一个语音接口 | 只在 Claude Code 桌面版上实测过，见下 |
| **按住说话**（另一半）<br>按住键说话，字进任何输入框 | 只要一个语音接口 | 任何人。跟 Claude 无关，单独能用 |
| **两半都要的** | 一个 **OpenAI 兼容**的语音接口的 **API key** | ⛔ 仓库里**不含任何密钥**，你得自己去服务商申请。默认接 [MOSS / MOSI](https://platform.mosi.cn)，换服务商只改 `api_base` 一个字符串 |

**为什么语音对话离不开 Claude Code**：它要在 Claude 回答完的那一刻拿到回复正文才能念，而这件事只有 Claude Code 的 hook 机制能告诉它。它挂的是 `Stop` / `UserPromptSubmit` 钩子，读的是 Claude Code 的会话记录。

### 试过什么、没试过什么

| | 状态 |
|---|---|
| **Claude Code 桌面版**（macOS app） | ✅ **只在这个上面开发和实测** |
| **Claude Code CLI**（终端里的 `claude`） | ⚠ **没试过。** 下面说清楚为什么不敢打包票 |
| 别的 AI 客户端 | ❌ 不支持 |

CLI 那条**已知有一处不一样**：徽章上「跟哪个会话说话」显示的名字，读的是桌面 app 自己的存储
（`~/Library/Application Support/Claude/claude-code-sessions/`）。本机实测：**200 个会话有对话记录，
只有 35 个在那个标题库里** —— 也就是说这个库不覆盖全部会话。取不到标题时会退回目录名、再退回会话 id
前 8 位，所以**列表不会空**，但名字会难认。

钩子和对话记录本身走的是两边共用的路径，所以 CLI **大概率能跑** —— 但那是推断，我没试过。
你在 CLI 上试通了或试不通，都欢迎开 issue 告诉我。

**不用 Claude Code 的人：**

- **按住说话照样能用**，一行都不用改。语音对话那半装了也不会启动，不影响任何东西。
- 你的客户端要是也有"回答结束时回调"的机制，改 `speak-hook.sh` 取文本那几行就能接上，其余不用动。

零第三方依赖，只要 Xcode Command Line Tools（`swiftc`）。Swift + 几个 Python 标准库脚本，没有包管理器。

## 为什么接了个外部模型，而不是用系统自带的

**因为测过三路。** 8 条录音，同一套口径算字错率（CER，越低越好）：

| 句子类型 | Claude 内置听写 | macOS 自带听写 | **MOSS** |
|---|---|---|---|
| 纯中文 | 6.7% | 3.7% | **1.5%** |
| 中英夹杂的技术句 | 15.6% | 32.5% | **6.6%** |
| 专有名词 | 22.2% | 16.7% | **27.8%** ⬅ 最差 |
| **总体** | 13.1% | 20.9% | **6.8%** |

三路都是**裸转写，没开词表**。MOSS 在纯中文、中英夹杂、总体三项都最优 —— 总体错误率是
Claude 内置的一半、macOS 的三分之一。

**但它有一项最差：专有名词 27.8%，比两个系统自带的都糟。** 这不是小事 ——
「甲项目」被听成另一个读音相近、**同样合法**的词组这类错，你读转写结果时根本看不出来。
而 MOSI 没有热词接口（实测），所以模型本体解决不了。

⇒ **这就是词表层存在的全部理由**，不是我没事干加的一层。选 MOSS 的完整判断是：
「准确率最优的那个，它唯一的短板恰好是后处理能补的那一类」。

一条实测原句（8 条之一，念的是普通开发指令）：

```
macOS 自带 → 你先跪皮一下frontmatter里的related字段然后come met do what tree分之
             别忘了跑Chak脚本全绿了才能迫使
MOSS      → 你先grip一下front matter里的related字段，然后commit到work tree分支，
             别忘了跑check脚本，全绿了才能push.
```

`commit 到 worktree` 变成 `come met do what tree`、`push` 变成 `迫使` —— 整段崩坏，后处理接不住。
MOSS 那版只剩 `grip→grep`、`front matter→frontmatter`，**词表一条规则就修好**。

### ⚠ 这些数字的边界

- **只有 8 条句子**。项目自己的评测口径写着：这个量级只够判「明显好／明显差／看不出差别」三档，
  **不要拿它做小数点后的比较**。
- **三路不是同一段音频**。系统听写不保存录音，MOSS 那轮是重录的。这进一步限制了可比性 ——
  只支持上面那三档判断。
- 语料是一个人的声音、一种口音、一种说话方式。你的分布不一样，结论可能不一样。
- **MOSS 并非全项达标**：当时定的四条验收线里，专名（要求 ≥80% 正确，实测 3 个测试专名全错）和
  延迟（要求 P90 ≤ 2 秒，实测 3.8 秒）**都没过**。选它是因为准确率的差距足够大、
  而短板那一项能靠词表补 —— 不是因为它全赢。
- 上表**不含**开了词表之后的数字。那个是在**构造词表所用的同一批句子**上测的，属过拟合，
  所以这里不引用。
- 换成任何 OpenAI 兼容的服务只要改 `api_base`。⚠ 但**词表是跟着引擎走的资产** ——
  换引擎之后，为上一个引擎攒的规则大概率对不上，得重攒。

## 装

```bash
git clone https://github.com/donjuangao/tingzhe.git && cd tingzhe
cp env.example .env.local
./build.sh
```

### 填你自己的 API key

`env.example` 是一个**空模板**，长这样（仓库里就这一行，没有值）：

```
TINGZHE_API_KEY=
```

拷成 `.env.local` 之后，把你自己在服务商那里申请的 key 填在等号后面。默认服务商是
[MOSS / MOSI](https://platform.mosi.cn)；换成任何 OpenAI 兼容的服务，就填那家的 key，
再改 `config.json` 里的 `api_base`。

**这个 key 是你的，不经过我，也不经过这个仓库：**

- ⛔ 仓库里**不含任何密钥** —— 你现在看到的每一个文件都在 GitHub 上公开可读，自己翻一遍就知道
- `.env.local` 被 `.gitignore` 挡着，不会被你误提交
- `./check.sh` 还会再查一遍：工作树里有没有密钥字面量、**git 历史里有没有**，两处都扫
- 请求直接从你的机器发到你填的那个 `api_base`，没有中间人

没填 key 的话，程序启动时会直接告诉你去哪个文件填，不会静默失败。

第一次跑要给两个权限：

| 权限 | 什么时候要 | 不给会怎样 |
|---|---|---|
| **麦克风** | 首次启动弹窗 | 直接退出 |
| **辅助功能** | 手动加：系统设置 → 隐私与安全性 → 辅助功能 → `tingzhe.app` | 还能用，但转写只进剪贴板要自己 ⌘V；单键热键退化成组合键 |

前台跑（能看日志）：

```bash
./tingzhe.app/Contents/MacOS/tingzhe
```

装成开机自启的常驻：

```bash
./install-agent.sh install     # status / uninstall
```

## 用

按住热键（默认右 ⌥）说话，松开出字。就这样。

**语音对话**：按 `⌃⌥V` 打开，屏幕右上角出现一个红色徽章。点它出面板：

- 跟哪个会话说话（显示的是你在 Claude 里给会话起的名字，不是仓库名——同一个仓开好几个会话时才分得清）
- **收音灵敏度** 三档 —— 咖啡馆点「迟钝」
- **发送方式** —— `攒成一条`（等你真停下来再发，边想边说不会被切碎）／ `一句一条`（说完一句立刻发）
- **快捷键** —— 点一下就能改，按下你想要的组合键即可（单键、轻点 ⌘/⌃/⌥ 都行）
- **按住说话** 用哪把键

⚠ 语音对话还要**接两个钩子**才生效，见下一节。

## 语音对话怎么接上

编辑 `~/.claude/settings.json`，加这两条（路径换成你 clone 的位置）：

```jsonc
{
  "hooks": {
    // 每轮回答结束 → 把回复念出来
    "Stop": [
      { "hooks": [ { "type": "command",
                     "command": "/你的路径/tingzhe/speak-hook.sh" } ] }
    ],
    // 每次你发消息 → 记下"你在跟哪个会话说话"，并拉起边写边念的进程
    "UserPromptSubmit": [
      { "hooks": [ { "type": "command",
                     "command": "/你的路径/tingzhe/active-session-hook.sh" } ] }
    ]
  }
}
```

已经有 `hooks` 段的话，把这两条**加进已有数组**，别整段覆盖。

| 文件 | 干什么 |
|---|---|
| `active-session-hook.sh` | 记录活跃会话，供徽章上那个列表使用 |
| `speak-watch.py` | **边写边念**：盯着回复落盘，每攒够一句就合成播放，所以第一声约 1 秒就出来，不用等整段写完 |
| `speak-hook.sh` | 兜底：`speak-watch.py` 没在跑时，整轮结束后念一次 |
| `speakify.py` | 口播过滤器：把代码块、路径、markdown 记号去掉，只留能听的部分 |

⚠ **这条链会把回复正文发给你配的 TTS 服务**，里面可能有你的代码和路径。不接这两个钩子，「按住说话」完全不受影响。

## 配

配置在 `config.json`（没有就从 `config.example.json` 复制；程序读不到会自动退回示例）。改完大多**热重载**，不用重启。

```jsonc
{
  "api_base": "https://api.mosi.cn/v1",   // 换服务商只改这里
  "hotkey": "rightOption",                 // 按住说话
  "voice_toggle_key": "ctrl+opt+v",        // 语音对话 开/关
  "voice_mute_key":   "ctrl+opt+m",        // 单方面静音（我不说，它还念给我听）
  "voice_mode_key":   "ctrl+opt+b",        // 攒成一条 ⇄ 一句一条
  "voice_gate_mult": 3.5,                  // 收音门槛 = max(voice_start_rms, 环境底噪 × 这个)
  "voice_start_rms": 0.035,                // 绝对下限：嘈杂环境真正起作用的是它
  "voice_send_after_ms": 3200,             // 停多久算"这句说完了"
  "tts_model": "moss-tts",                 // 念给你听用哪个模型
  "hud": true                              // 转写完在右上角闪一下结果；不想看就 false
}
```

**快捷键写法**：任意修饰键组合 + 任意主键，大小写随意。`ctrl+opt+v` · `cmd+shift+m` · `⌃⌥space` · `f13` · 单独一个 `cmd`（轻点一下）。设成 `none` = 不绑。

⚠ 不拦你选任何键。会误触发的会提醒（裸字母打字时会触发、左侧修饰键日常在用），但**选不选是你的事**。

## 专名词表

模型听不准的专有名词，写进 `dict.json`（没有就用仓库带的 `dict.example.json`）：

```json
[["work tree", "worktree"], ["front matter", "frontmatter"]]
```

⛔ **顺序有意义**：长模式必须排在短模式前面，否则短的会先咬掉一段。加词用

```bash
./tingzhe.app/Contents/MacOS/tingzhe --fix <听错的> <正确的>
```

它会自动插到正确位置。改完跑 `./check.sh`。词表**热重载**，不用重启。

⚠ **英文规则有词边界保护，中文没有。** 中文不分词，一条 2 字规则会把包含它的更长真词一起改掉。缓解办法是 `protect.json`（把不该被改的词指出来）和 `negatives.txt`（把误伤过的句子记一行，`check.sh` 从此永久守着）。**这是这个方法的上限，不是 bug。**

## 不做什么

- 不做多服务商兼容层（换 `api_base` 就够）
- 不做 Windows / Linux（整个东西建立在 macOS 的 TCC、AVAudioEngine、辅助功能 API 上）
- 不做说话人识别（嘈杂环境靠"近讲比远讲响一个数量级"这条物理事实，不靠模型）
- 不给语音对话做 Claude Code 桌面版之外的适配层（见开头那张表）
